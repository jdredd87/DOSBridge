# The DOS-side tools

Everything in the DOS Bridge client kit: the agent that lets a Windows PC
run jobs on a real DOS machine, and about thirty small tools for asking that
machine what it is and what it is doing.  Written by **StevenC** and
**Claude** (Anthropic).

All of them are plain 8086 code and run on anything from an original PC up;
where a faster CPU or a coprocessor helps, it is detected at run time.  All
of them **print through DOS**, so over the bridge their answer comes back as
text -- even the ones that capture the screen.  Every tool links to its
source; the shared units they use (`About`, `Cpu`, `Tester`, `VGA`, `Net`,
`Tftp`) are in [`starter`](.) beside them, and
[`README.md`](README.md) there is how to build and write your own.

## Installing

Copy the whole client folder to the DOS machine -- floppy, network share, a
PicoMEM disk image, whatever it can read -- and from that folder:

```
INSTALL              mTCP, if you have it, in C:\MTCP
INSTALL C:\MTCP      mTCP somewhere else (it is optional)
```

That creates `C:\AI` (the agent), `C:\AGENT` (its state), `C:\TOOLS` (these
tools) and `C:\WORK` (scratch), and writes `C:\AUTOEXEC.NEW` as a
suggestion.  **It never changes `AUTOEXEC.BAT` or `CONFIG.SYS`.**  Merge the
packet driver line and the agent into `AUTOEXEC.BAT` by hand, then reboot; the
Windows side should see a poll within seconds (`dosctl status`).

| file | |
|---|---|
| `INSTALL.BAT` | the installer above |
| `AUTOEXEC.NEW` | a suggested `AUTOEXEC.BAT`: packet driver, then the agent |
| `NET.CFG` | the bridge's network settings -- this machine's static address, the Windows PC's, the gateway. Installed as `C:\AI\NET.CFG` |
| `MTCP.NEW` | an example mTCP config with the same static address, if you use mTCP. Your own `MTCP.CFG` is never touched |
| `README.TXT` | the same instructions, readable on the DOS machine |
| `VERSION.TXT` | which kit build this is |

**You supply** a packet driver for your network card (`PM2000.COM` for a
PicoMEM, `NE2000.COM`, a vendor's) and `CHOICE.COM` from DOS 6.22.  mTCP is
not needed: the bridge has its own IPv4/UDP stack.  **Use a static address,
never DHCP** -- a lease nothing renews eventually takes the machine off the
network until somebody walks over to it.

`C:\TOOLS` is not on the `PATH` unless you put it there, so call a tool by
its full path at the prompt or over the bridge:

```
C:\TOOLS\HWINFO
dosexec "C:\TOOLS\HWINFO"          from Windows; output and exit code come back
dosrun HWINFO.EXE                  from Windows; pushes a fresh copy and runs it
```

## The agent

These run the bridge.  The agent loop calls them; you rarely will.

| | |
|---|---|
| `AI.BAT` | **the agent loop**, installed as `C:\AI\AI.BAT`: polls the Windows PC for a job, runs it, sends back the output and exit code. Its crash guard covers driver tests (`dosdrv`): the next boot reports whether the machine survived the driver. A text file -- read it |
| [`UGET`](uget.pas) | fetch a file from the bridge over UDP (TFTP, windowed) |
| [`UPUT`](uput.pas) | send a file to the bridge over UDP |
| [`NETCHK`](netchk.pas) | when polls keep failing: is it this machine's link, or the far end? Reboots only if neither the server nor the router answers |
| [`KEYHIT`](mkkeyhit.py) | exit 1 if ScrollLock is on -- **ScrollLock stops the agent** at its next poll. 22 bytes, generated by `mkkeyhit.py` |
| [`SCRLOFF`](scrloff.asm) | turn ScrollLock off, keyboard lamp included, so a restarted agent does not stop again at once |
| [`F10HIT`](f10hit.asm) | exit 1 if F10 was pressed -- **F10 at the agent opens ASK** |
| [`ASK`](ask.pas) | type a request to the Windows side: a Claude Code session watching for it (`askwatch.py`) does it and answers on this screen |
| [`ELAPSED`](elapsed.asm) | the job stopwatch behind the one-line result the agent prints after each job |
| [`REBOOT`](reboot.asm) | warm reboot (16 bytes) |
| [`COLDBOOT`](reboot.asm) | cold reboot, with the full POST (16 bytes) |

```
UGET server name file [POLL] [-C crc] [-V]
        exit 0 arrived, 1 transfer failed, 2 no driver/config, 3 CRC mismatch
UPUT server file name [-V]
        exit 0 acknowledged, 1 transfer failed, 2 no driver/config
NETCHK server [/N polls] [/R reboots]     once per failed poll (AI.BAT)
NETCHK /PROBE server                      probe now, print, change nothing
NETCHK /OK                                after a good poll
NETCHK /STATUS                            the counters and C:\AGENT\NETCHK.LOG
ASK [box] outfile         an empty line sends, an empty first line cancels
ELAPSED /S                start the stopwatch
ELAPSED text              print text and the time since, on one row
```

To stop the agent at the keyboard, turn ScrollLock on and wait for the next
poll.  To restart it, `C:\AI\AI.BAT`.  [`docs/agent.md`](../docs/agent.md)
has every way it can go quiet and what each looks like.

## The machine

| | |
|---|---|
| [`SYSINFO`](sysinfo.pas) | DOS version, free memory, CPU, coprocessor -- a quick pass/fail check. Exit code: failures |
| [`HWINFO`](hwinfo.pas) | **the full sweep**: CPU, BIOS, memory (conventional, EMS, XMS), the equipment word, ports, video and VESA, every drive from C: up. Read-only |
| [`FPU`](fpu.pas) | is a coprocessor fitted, and which one? `/T` also runs arithmetic tests |
| [`FPUPROBE`](fpuprobe.pas) | coprocessor timing diagnostic: the raw words at each delay. Safe with or without one |
| [`BENCH`](bench.pas) | what this machine is fast and slow at, in operations per second: 16- and 32-bit arithmetic, calls, shifts, video writes, the coprocessor |
| [`SERIAL`](serial.pas) | the COM ports: base address, baud rate and framing as set, modem lines, owner |
| [`MOUSE`](mouse.pas) | exercise the mouse driver (INT 33h): range of travel and every click |

```
FPU [/T]        exit 0 present (and /T passed), 1 none, 2 a test FAILED
BENCH [ticks-per-test]                default 18, about a second each
SERIAL                                probe every port the BIOS knows
SERIAL /T                             also identify the UART (writes a register)
SERIAL n /M secs                      monitor COM n, dump what arrives
SERIAL n /ID                          pulse DTR/RTS, read a mouse's ID byte
MOUSE [seconds]                       default 10 -- move it and click
```

**`FPU /T` is opt-in for a reason:** x87 arithmetic carries `WAIT`, and a
`WAIT` with no coprocessor answering hangs the machine.  The detection on its
own never waits and is always safe.

## Files and memory

| | |
|---|---|
| [`HD`](hd.pas) | hex dump of any window of any file, with its size and CRC-32 -- check a copied file without copying it back |
| [`DSTAT`](dstat.pas) | recursive totals: files, directories, bytes, and the biggest directories |
| [`MEMMAP`](memmap.pas) | walk DOS's memory chain: every block, its owner and size |
| [`DEVS`](devs.pas) | the DOS device driver chain; `DEVS NAME` answers "is it loaded?" as an exit code |
| [`IVT`](ivt.pas) | the interrupt vectors, each attributed to the program that hooked it |

```
HD file [offset] [count]      default: the first 256 bytes
DSTAT [path]                  default: the current directory
MEMMAP [/F | /S]              /F free blocks only, /S summary only
DEVS [NAME]                   with NAME: exit 0 loaded, 1 not
IVT [/A | nn]                 /A all 256, nn one vector in hex
```

## Video

| | |
|---|---|
| [`VIDCHK`](vidchk.pas) | colour or mono? As an exit code, for a batch file to branch on |
| [`VMODES`](vmodes.pas) | every video mode the BIOS and VESA offer -- and with `-t`, whether each really sets |
| [`VESACHK`](vesachk.pas) | what the VESA BIOS claims: version, memory, modes. Changes nothing |
| [`SCRAPE`](scrape.pas) | print the text screen through DOS, so what a program left on screen comes back as text |
| [`VSHOT`](vshot.pas) | print a 320x200 graphics screen as ASCII art |
| [`GTEST`](gtest.pas) | draw a known test pattern and leave it up, for `VSHOT` |

```
VIDCHK                exit 0 colour, 1 mono, 2 the BIOS cannot say
VMODES [-t] [-d secs] [mode]
        -t      set each mode, check it, restore text
        -d n    also draw a pattern and hold it n seconds -- needs someone
                at the monitor; the log says OK for a mode it cannot show
SCRAPE [/A] [/R]      /A attributes too, /R keep trailing blanks
VSHOT [/K]            /K keep the graphics mode set afterwards
```

`SCRAPE` and `VSHOT` read what the *previous* program left, so run them in
the same job straight after it: `dosexec "GTEST" "VSHOT"`.

## Network

These talk to the packet driver directly -- no TCP/IP stack needed.

| | |
|---|---|
| [`PKTDRV`](pktdrv.pas) | find the packet driver and describe it. Read-only, opens no handle. Exit code: how many drivers were found, so **1 is healthy** |
| [`ARP`](arp.pas) | who has this address? Or sweep a whole /24 |
| [`NTP`](ntp.pas) | ask a time server the time. Never sets the clock |
| [`PKTCAP`](pktcap.pas) | capture Ethernet frames |

```
PKTDRV [vec]                      vec in hex, e.g. 60
ARP address [-w secs]             exit: the number of hosts that answered
ARP -scan a.b.c [-w secs]
NTP [address]                     default: the gateway in NET.CFG
PKTCAP [secs] [type|ALL] [vec]    default 5 s of ARP; 0800 is IPv4
```

**With `ALL`, the frames `PKTCAP` captures are frames nobody else gets** --
on a machine whose only card is the bridge's, that takes the bridge off the
air for the length of the capture.  Give it the vector of a second driver when
there is one.  Every address here is a number: there is no DNS.

## Sound and input

| | |
|---|---|
| [`BEEP`](beep.pas) | the PC speaker -- a note, or an alert for when the machine needs a human |

```
BEEP                        one 880 Hz note
BEEP freq ticks [count]     ticks of 55 ms
BEEP ALERT                  a rising "look at me"
BEEP DONE                   a falling "finished"
```

Compose it around anything that needs someone at the machine:
`dosexec "BEEP ALERT" "MOUSE 15" "BEEP DONE"`.

## Driving interactive programs

DOS runs one program at a time, so nothing can type into a running program
from outside -- except an interrupt handler.  These two are resident, and are
how an interactive program is driven from Windows.

| | |
|---|---|
| [`KINJ`](kinj.asm) | **scripted keystrokes and screen captures**: load a script of keys and waits, run the program, read back what was on screen at each step. [`mkkeys.py`](mkkeys.py) compiles a script; [`session.txt`](session.txt) is a worked one |
| [`KNET`](knet.asm) | **a live keyboard over the network**: type on Windows with [`sendkeys.py`](sendkeys.py), and the keys arrive in whatever is running on the DOS machine |

```
KINJ file.KI        load a script and go resident
KINJ /D             print the screens it captured
KINJ /S             what is loaded, how far through
KINJ /U             unhook and free the memory
KNET [port]         go resident and take keys from the network
KNET /T             prove the keys arrive WITHOUT going resident -- start here
KNET /S | /U        status | unload

python mkkeys.py session.txt > SESSION.KI         on Windows
python sendkeys.py 192.168.1.255                  on Windows: type, it goes
```

Both feed keys through the BIOS (INT 16h), so a program that reads the
keyboard hardware itself -- most action games -- will not see them.  KNET's
keys must be sent to the broadcast address; [`knet.md`](../knet.md) has why,
and the rest of its four hazards.

## Demos and extras

The demos -- the raycaster, the parallax and scrolling demos, the fractal,
Mozart on an AdLib -- are in the kit's `DEMOS` folder and install into
`C:\TOOLS` beside these; [`demos/README.md`](demos/README.md) describes
them.  Optional DOS enhancements -- a faster `ANSI.SYS`, a `DOSKEY` with TAB
completion, a UMB manager, XMS for 8086 machines, network and sound card
probes -- are in the kit's `EXTRAS` folder.  Nothing installs those: each
has a `.TXT` saying how.

## Exit codes

DOS can only test an exit code with `IF ERRORLEVEL n`, so every tool keeps
its codes at 20 or under and documents them above.  Where nothing is listed,
0 means it ran.  Over the bridge, a command that is not an external program
(`DIR`, `TYPE`, `ECHO`) has no exit code at all: read its output instead.
